# ROTFALL

> **This game was written with AI.** The code, shaders, music, sound effects, Blender scene and this
> README were generated by [Claude](https://www.anthropic.com/claude) (Opus 5.5) using Claude Code,
> directed by a human who chose the features and played the results. Expect the strengths and blind
> spots of that process. The automated tests pass, but the Windows build has only been run under Wine,
> and multiplayer has only been run between processes on a single machine.

A top-down, third-person 3D wave survival shooter, written in Rust. Hold the reactor against
an endless horde: build walls and traps, deploy sentries, buy bigger guns, and keep moving.

Everything you see and hear is generated by code. The only image files are the menu art, and those are
rendered in Blender from a script in this repository.

```sh
cargo run --release
```

It runs on Linux and Windows with a Vulkan or OpenGL driver; see below for building for Windows. Sound needs `libasound.so.2`, which is
loaded at runtime; without it the game still runs, silently. No `pkg-config` or ALSA headers
are needed to build.

## Controls

| Input | Action |
| --- | --- |
| `WASD` / mouse | Move / aim |
| `LMB` | Shoot |
| `R` | Reload |
| `Shift` | Sprint |
| `Space` | Dodge roll (brief invulnerability) |
| `G` | Throw grenade at the cursor |
| `1`-`9`, wheel, `Q`/`E` | Switch weapon |
| `F` | Flashlight |
| `Tab` | Armory: buy guns, ammo, grenades |
| `B` | Build mode: `LMB` place (drag for walls and traps), wheel or number keys to select, `RMB` exit |
| `U` / `T` / `X` | Upgrade / repair / sell what the cursor is on |
| `Enter` | Start the next wave early, for a scrap bonus |
| `-` / `=` | Camera zoom |
| `F5` / `F9` | Quicksave / quickload |
| `P` | Player list and server panel (multiplayer) |
| `F11` | Fullscreen |
| `M` / `F3` / `H` / `Esc` | Music / performance counters / help / pause |

The game ends when the reactor falls. When you fall, you redeploy after 8 seconds, unless
you are playing permadeath.

## Modes

**Standard.** Redeploy on death. Wave clears autosave, `F5` saves any time, and closing the
window saves too. *Continue* appears on the title screen.

**Permadeath.** One life. Dying ends the run and erases its save, and there is no quickload.
You can still suspend a run by quitting and resume it later.

**Co-op, for up to 8 players.** Everyone shares the scrap, the base and the reactor. The horde
hunts whoever is closest.

Saves, settings and records live in `~/.local/share/rotfall` (or `$XDG_DATA_HOME/rotfall`). A save
holds the whole battle: zombies, structures, projectiles, inventories. It leaves out corpses, particles
and painted gore, which are cosmetic.

## Hosting

**From the game:** *Multiplayer → Host a server*. Set a name, port, player cap, optional password and
permadeath, then start. You land in a lobby where people can join and build, and `Enter` begins the
match. `P` opens the server panel: join address, players and pings, kick, save.

**Dedicated, with no window or GPU:**

```sh
rotfall --server --port 27416 --name "Night Shift" --max-players 6 --password secret
rotfall --server --load ~/.local/share/rotfall/host.sav     # resume a saved match
```

Console commands: `status`, `start`, `kick NAME`, `save`, `quit`. Any player can start the match with
`Enter`. It autosaves at wave clears, pauses while empty, and starts a fresh match after a game over.

**Joining:** *Multiplayer → Join a server*. Servers on your network are listed automatically (UDP port
27417). Otherwise enter `host` or `host:port`. Rejoining under the same name gets your slot and
inventory back.

**Over the internet,** the host forwards TCP port 27416 on their router and shares their public address.

Things to know about the network design:

- Play with people you trust. Each client is the authority on its own position, which keeps movement
  instant at any ping but means a modified client could teleport. Damage, purchases and everything else
  are decided by the host.
- The password is sent unencrypted. It keeps strangers out of a game; it is not real security, so
  don't reuse an important one.
- Bandwidth was about 100 KB/s per client in a test battle with around 280 zombies.

## What's in it

- **18 guns**: sidearm, SMG, rifle, pump and auto shotguns, magnum, twin SMGs, sniper, LMG, grenade
  launcher, rocket launcher, flamethrower, freeze gun, chain lightning, bouncing sawblades, beam
  laser, spin-up minigun, railgun.
- **8 zombies**: walkers, runners, crawlers, exploding bloaters, acid spitters, charging brutes,
  screamers that enrage the crowd, and a Titan boss every fifth wave. Limbs come off, and a zombie
  that loses a leg keeps coming as a crawler.
- **16 structures**: wood and steel walls, gates, spike traps, razor wire, mines, seven sentry
  types (MG, scatter, flame, tesla, gatling, rocket, mortar; each upgrades twice), floodlights,
  ammo depots, repair bays.
- **Chain reactions**: barrels cook off, fire spreads between bodies, frozen zombies shatter, and
  gore permanently paints the ground.

## How it's built

| Path | What it is |
| --- | --- |
| `src/render/` | **Custom renderer.** wgpu is used only as the GPU API. Forward HDR shading with a CPU-binned world-space light grid, sun and flashlight shadow maps, instancing, MSAA, a persistent world-space decal layer, billboard particles, a bloom pyramid, tonemapping, and a bitmap-font UI batcher. All meshes are built procedurally in `mesh.rs`. |
| `src/ragdoll.rs` | **Custom ragdoll engine.** Position-based dynamics on a 16-joint skeleton, with joint limits, torso bracing, breakable limbs, partial bodies, static collision, pile-ups and sleeping. Living characters are posed on the same skeleton, so death hands over with no visible pop. |
| `src/audio/` | **Soundtrack and SFX.** Seven original tracks written as note data and synthesized live, with layers that follow the battle's intensity. All effects are synthesized at startup. Output goes through a small runtime-loaded ALSA binding. |
| `src/game/` | Simulation: flow-field navigation, zombie AI, combat, base building, waves, HUD, and a bot that plays the game. `net.rs` is the co-op protocol and `save.rs` the save format. |
| `tools/menu_scene.py` | **Menu art.** A Blender scene built entirely from script. `tools/render_menu_art.sh` re-renders it to `assets/`, which are compiled into the game. |

Dependencies are limited to `wgpu`, `winit`, `glam`, `bytemuck`, `pollster`, `libc` and `png`.

## Windows

A Windows build comes from `tools/build_windows.sh`, run on Linux with `zig` and the `rustup` target
`x86_64-pc-windows-gnu`. It produces `dist/rotfall-windows-x64.zip`. The `.exe` is unsigned, so
SmartScreen warns on first launch. Saves go to `%APPDATA%\rotfall`, along with a `crash.log` after a crash.

## Development tools

```sh
cargo test --release                                    # full suite, including bot-played games
cargo test --release balance -- --ignored --nocapture   # six full bot games, with the results
rotfall --capture out --times 20,40 --wave 12 --scrap 30000   # bot plays; writes PNGs, no window
rotfall --capture out --times 6 --screen armory         # also: title, build, help, pause, menu_host...
rotfall --capture host --times 40 --host --port 27511 --wave 8   # a bot hosts a real server
rotfall --capture guest --times 30 --connect 127.0.0.1:27511     # a scripted client joins it
rotfall --bench 15 --wave 14 --size 1920x1080           # sim and GPU timing on this machine
rotfall --render-music boss 60 1.0 boss.wav             # menu|build|a|b|c|boss|over SECS INTENSITY FILE
```

Also: `--scale 0.5` for lower render resolution on weak GPUs, `--no-vsync`, `--no-audio`,
`--seed N`. Setting `ROTFALL_LOG=1` prints frame stats.
